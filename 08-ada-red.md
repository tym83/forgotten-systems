# Ada RED (Intermetrics) — разведка источников

Проверено 2026-09-21.

## История конкурса (уточнённая)

Полковник Билл Уитакер поставил задачу общего языка для министерства обороны США,
Дэвид Фишер собирал требования по родам войск. Серия документов требований:
**Strawman → Woodenman → Tinman → Ironman → Steelman** (июнь 1978).

Первая фаза конкурса на «DoD-1» дала **16 языковых предложений**. Из них профинансировали
четыре, обезличенных цветами:

| Цвет | Организация | Ведущий |
|---|---|---|
| **Red** | Intermetrics | Ben Brosgol |
| **Blue** | SofTech | John Goodenough |
| **Green** | CII-Honeywell-Bull | Jean Ichbiah |
| **Yellow** | Stanford Research International (SRI) | Jay Spitzen |

Апрель 1978: Blue и Yellow отсеяны, Red и Green идут дальше.
Май 1979: побеждает Green → становится Ada.

**Важная деталь:** Intermetrics во второй фазе не стала дорабатывать свой первый проект
(он назывался **REDL**), а сделала **радикальный редизайн** — получился новый язык **RED**.
То есть «красных» языков два, и целевой — RED, март 1979.

## ⚠ Поправка: компилятор БЫЛ

Ранее я говорил, что на этом языке никто никогда ничего не запускал. Это неверно.

**Intermetrics довела до работоспособного состояния транслятор RED** (руководил Mark Davis).
Но по условиям контракта транслятор **не мог учитываться при выборе языка**, поэтому
служил только внутренним прототипом-операционным определением. После победы Green
Intermetrics поддержала общий язык, и оба «красных» языка исчезли.

Правильная формулировка для статьи: **язык, у которого был работающий компилятор, который
не показали никому и который не сохранился.** Это сильнее и точнее, чем «никогда не
компилировался».

## Что доступно

### RED Reference Manual (март 1979)
- **Полная HTML-транскрипция:** https://www.iment.com/maida/computer/redref/
- Транскрибировала **Mary Van Deusen** — один из авторов оригинального руководства
  (писали вдвоём с **John Nestor**). Выложено к 30-летию конкурса.
- До этого документы **не были публично доступны** после окончания конкурса.
- **PDF на DTIC:** ADA219453, https://apps.dtic.mil/sti/tr/pdf/ADA219453.pdf
  — ⚠ DTIC отдаёт 403 на скриптовый доступ (бот-защита); из браузера, видимо, откроется
- **Зеркало на Internet Archive:** идентификатор `DTIC_ADA219453`
  («DTIC ADA219453: Red Language Reference Manual») — чистый скачиваемый PDF
- Контракт MDA903-77-C-0330, копирайт 1979 Intermetrics

**Оглавление (полное, всё на месте):**
0 Acknowledgments · 1 Introduction · 2 Lexical Structure · 3 Program Structure ·
4 Types · 5 Expressions · 6 Statements · 7 Procs, Funcs & Parameters · 8 **Capsules** ·
9 Exception Handling · 10 **Multitasking** · 11 Overloading & Generics ·
12 Machine-Dependent Facilities · 13 Advanced Definitions · 14 Low-Level Facilities ·
A High-Level I/O · B Pragmats · C Built-In Types · D Exceptions · E Glossary ·
F Diagram Xref · G Index

**Синтаксис задан flow-диаграммами** (раздел 1.6: для лексических элементов и для
конструкций языка) → грамматика фактически дана, парсер писать есть по чему.

### RED Language Design Rationale (март 1979, Ben Brosgol)
- **Полная HTML-транскрипция:** https://www.iment.com/maida/computer/redrat/
- Объясняет, ПОЧЕМУ приняты решения — разобраны альтернативы, которые отвергли
  (эквивалентность типов: чисто именная / структурная / single-instance generators /
  расширенная именная; классы связывания параметров; непрозрачность типов)
- **Приложение B: Contract Test Problems**
- **Приложение C: Sample RED Programs** ← примеры от Абрахамса (NYU), Хаббарда, Кнобе,
  Левина (Boston College), Смита (Rutgers)

**Это главный де-риск проекта:** есть контрактные тестовые задачи и готовые примеры
программ, то есть корпус для проверки компилятора существует с первого дня.

### Steelman
Свободно доступен: dwheeler.com/steelman, adahome.com, Wikisource. Служит опорой там,
где спецификация RED окажется неполной — все четыре проекта обязаны были ему удовлетворять.

### Blue и Yellow — публично не найдены

Проверено методично: поиск по заголовкам и по всем полям метаданных в зеркале DTIC на
Internet Archive, плюс общий веб-поиск. Контрольный запрос на «red language» находит
ADA219453 — значит, метод работает; «blue language» и «yellow language» в связке с DTIC
дают ноль.

Пробовал также просматривать соседние номера DTIC — бесполезно: номера AD присваиваются
по дате поступления, а не по теме, у Green-документов соседи никак не связаны.

**Вывод:** Blue и Yellow в открытом вебе отсутствуют. Остаются варианты: прямой поиск на
apps.dtic.mil из браузера (скриптовый доступ блокируется), запрос через библиотеку,
обращение к сообществу историков Ada и лично к участникам (Mary Van Deusen выложила
RED — возможно, знает и про остальные).

Приоритет низкий: Red — финалист, задокументирован полностью, и именно он интересен.

### 🎁 Зато нашлось другое: GREEN до того, как он стал Ada

В зеркале DTIC на Internet Archive лежат три документа под цветовым именем, то есть
ДО переименования в Ada:

| Идентификатор | Документ |
|---|---|
| `DTIC_ADA070753` | The Green Language; An Informal Introduction |
| `DTIC_ADA073714` | The Green Language. A Formal Definition |
| `DTIC_ADA070752` | Set of Sample Problems for DOD High Order Language Program. **GREEN Solutions** |

Третий — самый ценный. Название прямо подразумевает, что тот же набор задач решался
каждой командой, и это стыкуется с **приложением B рационале RED «Contract Test
Problems»**.

**Отсюда выпуск, который не требует ни строчки кода:** взять одни и те же контрактные
задачи и положить рядом решение на RED и решение на GREEN. Сравнение двух Ад на
идентичном материале, обе в дофинальном виде. Такого сопоставления, насколько я вижу,
никто не публиковал.

Плюс «формальное определение» Green — редкая вещь сама по себе: формальная семантика
языка до того, как он стал стандартом.

## Что такое RED на самом деле

Из введения: язык для встроенных применений МО США по требованиям Steelman, сочетающий
обычные возможности языков высокого уровня с новыми средствами для абстрактных типов
данных, обработки исключений, многозадачности, обобщённых определений и доступа к
машинно-зависимым средствам. Заявленные цели — модульность, абстракция, надёжность,
эффективность, причём отдельно: **«использование ассемблера не должно быть необходимым»**.

### Чем отличается от Ada

| RED | Ada |
|---|---|
| **Capsule** | package |
| **Многозадачность на почтовых ящиках** (mailbox variables), Act priority scheduler, region statement, data lock variables | рандеву (entry/accept) |
| **Guard statement** | блок обработчиков |
| **Indirect types** | access types |
| **Interfaces / signatures / translation-time property lists** | generic formal parameters |
| **Manifest expressions и условная трансляция** | — |
| Union types, set types как агрегатные типы | variant records |
| Упорядоченные и **неупорядоченные** перечисления | — |
| **ASSERT** на уровне объявлений и в теле | появится только в Ada 2012 как контракты |

Модель параллелизма — ключевое расхождение: **RED это передача сообщений, Ada это
рандеву**. Для ядра в стиле Tandem NonStop почтовые ящики подходят лучше, чем рандеву.

### Как это выглядит (из приложения C)

```
CAPSULE matrix_vector_package EXPORTS ALL;
CONST mvprec := 6;
CONST maxdim := 100;
ABBREV mvfloat : FLOAT(mvprec, mvmin .. mvmax);
ABBREV dim : INT(2 .. maxdim);
TYPE matrix(m : dim, n : dim) : ARRAY INT(1 .. m), INT(1 .. n) OF mvfloat;
TYPE vector(n : dim) : ARRAY INT(1 .. n) OF mvfloat;

FUNC *(READONLY b : matrix, READONLY c : matrix) => matrix(b.m, c.n);
    ASSERT b.n = c.n;
    VAR a : matrix(b.m, c.n);
    % Compute a := bc
    ...
END FUNC *;

FUNC *(READONLY b,c : vector(3)) => vector(3);   % перегрузка по РАЗМЕРУ
```

Что здесь поражает для 1979 года:

- **Тип результата вычисляется из значений аргументов**: `=> matrix(b.m, c.n)`.
  Размерности живут в типе.
- **Перегрузка по значению параметра типа**: отдельная реализация `*` для `vector(3)`
  (векторное произведение). Сегодня это делают const generics в Rust.
- **ASSERT прямо в сигнатуре/теле** как часть языка.
- **Классы связывания параметров** явные: `CONST`, `READONLY`, `VAR`.
- Точность И диапазон как часть типа float.
- Комментарий — `%`, прагма — `PRAGMAT INLINE`.

## Что это значит для проекта

**Риск «спеки нет» снят полностью.** Есть руководство, есть рационале с объяснением
альтернатив, есть синтаксические диаграммы, есть тестовые задачи и примеры программ,
есть Steelman как опора.

**Объём работы не изменился** — это всё ещё три-шесть месяцев неполной занятости до
пригодного подмножества при фронтенде на LLVM или C.

**Сюжет стал лучше:** не «язык, который никогда не работал», а «язык, который работал
ровно один раз внутри одной компании, проиграл по правилам, запрещавшим учитывать его
компилятор, и исчез».

**Юридически:** руководство под копирайтом Intermetrics 1979, транскрипцию выложил один
из авторов. Реализация языка по спецификации вопросов не вызывает; обширное
цитирование/перепубликация документа — вызовет, это отдельно проверить.
