## 1. Каноническое состояние

Единственное определение того, что считается «состоянием машины». Обе модели обязаны
уметь его отдавать.

```c
/* state.h */
typedef struct {
    uint32_t pc;
    uint32_t r[16];
    uint32_t h;              /* старшие биты MUL / остаток DIV */
    uint8_t  n, z, c, v;     /* флаги */
    uint8_t  irq_enabled;
    uint32_t spc;            /* сохранённый контекст прерывания */
} cpu_state_t;

/* Записи в память за шаг — сравниваются отдельно, чтобы не гонять всю RAM */
typedef struct {
    uint32_t addr;
    uint32_t data;
    uint8_t  width;          /* 1 = байт, 4 = слово */
} mem_write_t;

typedef struct {
    cpu_state_t  cpu;
    mem_write_t  writes[MAX_WRITES_PER_STEP];
    int          n_writes;
} step_result_t;

int  state_equal(const cpu_state_t *a, const cpu_state_t *b);
void state_diff_report(FILE *out, const cpu_state_t *ref, const cpu_state_t *dut);
```

✅ **Закрыто ревью.** Шаг = **завершение инструкции (retire)**, не такт: LD/ST = 2 такта,
FAD = 4, FML = 26, FDV = 27, MUL/DIV = 34. Строб retire — фронт при `~stall`, но
**`stall` наружу не выведен** (`RISC5.v:169`) → нужен `/*verilator public*/` или
отладочный порт.

## 2. Дифференциальный прогон (главный инструмент)

```c
/* diff_main.c */
int run_differential(const char *disk_image, uint64_t max_steps)
{
    ref_t *ref = ref_init(disk_image);
    dut_t *dut = dut_init(disk_image);

    for (uint64_t step = 0; step < max_steps; step++) {
        uint32_t pc   = ref_pc(ref);
        uint32_t insn = ref_peek_word(ref, pc);

        step_result_t r_ref, r_dut;
        ref_step(ref, &r_ref);
        dut_step_until_retire(dut, &r_dut);

        if (!state_equal(&r_ref.cpu, &r_dut.cpu) ||
            !writes_equal(&r_ref, &r_dut)) {
            fprintf(stderr,
                "РАСХОЖДЕНИЕ на шаге %llu\n"
                "  PC   = 0x%08X\n"
                "  insn = 0x%08X  (%s)\n",
                step, pc, insn, disasm(insn));
            state_diff_report(stderr, &r_ref.cpu, &r_dut.cpu);
            writes_diff_report(stderr, &r_ref, &r_dut);
            dump_context(ref, dut, pc);      /* ±16 инструкций вокруг */
            return 1;
        }

        if (step % CHECKPOINT_EVERY == 0)
            checkpoint_full_memory(ref, dut, step);   /* редкая полная сверка RAM */
    }
    return 0;
}
```

**Почему сверка записей, а не всей памяти:** полное сравнение мегабайта после каждой
инструкции убьёт скорость. Полная сверка — раз в N шагов, чтобы поймать расхождения,
которые DUT «не заметил» (например запись мимо шины).

### 🔴 Пять исправлений, без которых стенд не заработает

1. **Строб retire** вместо такта — см. выше
2. **В эталоне НЕТ прерываний вообще** (ни `SPC`, ни `RTI`, ни `irq`) → **T1.7 сверять не с чем**: писать свой эталон или признать отсутствие golden-модели
3. **Разная разрядность PC**: RTL `reg [21:0]`, сброс на `0xFFE000`; эмулятор 32-битный индекс слова, `ROMStart 0xFFFFF800`. Совпадают только из-за алиасинга PROM → **сравнивать по модулю 2²²**
4. **Эталон пишет в память то, чего в железе нет**: `risc.c:130-133` кладёт `"Sizg"` и размеры экрана на `DisplayStart` → побайтовое сравнение RAM упадёт на **нулевом** шаге. Исключить
5. **Эвристика `progress`**: `risc_run` выходит, как только Oberon 20 раз подряд читает миллисекундный счётчик → **молча выйдет раньше запрошенного**, и состояния разъедутся не из-за бага в RTL. **Патчить `risc->progress`** (`risc.c:165`, одна строка)

Плюс: **диффтест ограничить RAM, IO исключить** — эмулятор моделирует устройства по-своему.
И: **ISS не тактово-точный вообще** (`risc_run` считает инструкции) → T0 сверяет
архитектурное состояние, **такты берутся только из RTL**.

**Режимы прогона:**
| Режим | Что делает | Когда |
|---|---|---|
| `--directed FILE` | грузит тест из `directed/`, прогоняет до HALT | на каждый коммит |
| `--random SEED N` | генерирует и прогоняет N случайных инструкций | ночная сборка |
| `--boot` | полная загрузка Oberon с образа до готового экрана | на каждый коммит |
| `--trace FILE` | воспроизводит записанную трассу | при разборе бага |
| `--bisect` | двоичный поиск первого расхождения в длинной трассе | при разборе бага |

## 3. Направленные тесты: формат

✅ **Закрыто.** Ассемблера для RISC5 не существует (в Project Oberon его нет вообще;
стороннее — только `waz-xyz/r5asm`, WIP). Выбран путь (а): **мини-ассемблер на Python,
`asm.py` в этой же папке, работает, самотест из 14 проверок кодирования проходит.**

Практичная альтернатива для части тестов: писать их прямо на Обероне —
`SYSTEM.PUT`, `SYSTEM.LDREG`, `SYSTEM.REG`, `SYSTEM.COND`, `SYSTEM.H` уже есть
в универсуме ORB.

Формат теста — с ожидаемым результатом прямо в файле:
```
; t1_flags.s — N и Z ставятся при ЛЮБОЙ записи в регистр, включая LD
        MOV  R0, 0
        MOV  R1, 100
        ST   R1, R0, 0        ; Mem[0] = 100
        MOV  R2, -1           ; портим флаги
        LD   R3, R0, 0        ; загрузка 100 -> N=0, Z=0
; EXPECT R3 = 100
; EXPECT N = 0
; EXPECT Z = 0
        MOV  R4, 0
        ST   R4, R0, 4
        LD   R5, R0, 4        ; загрузка 0 -> Z=1
; EXPECT Z = 1
        HALT
```

`; EXPECT` разбирается оснасткой и проверяется в точке, где стоит. Это позволяет тесту
быть одновременно документацией — важно, потому что тесты пойдут в текст статьи.

## 4. Приоритет направленных тестов

Отсортировано по вероятности ошибки в реализации, а не по порядку в спецификации:

| Приоритет | Тест | Почему легко ошибиться |
|---|---|---|
| 🔴 1 | **T1.2 флаги** | N и Z ставятся на ЛЮБОЙ записи. Не только `LD`: **`regwr = ~p & ~stall \| (LDR & …) \| (BR & cond & v & ~stallX)` — принятый BL/BLR пишет R15 и ставит N=0, Z=0.** Store флаги не трогает |
| 🔴 2 | **T1.7 прерывания** | вход на `0x00000004`, сохранение/восстановление NZCV+PC, **H не сохраняется** |
| 🔴 3 | **T1.4 плавающая** | 🔴 **фиксировать поведение Вирта, НЕ IEEE**: денормали и нули схлопываются в 0, деление на 0 → насыщение, **NaN как класса нет**, один guard-бит, округление round-half-up. Эталон — `risc-fp.c`, а не стандарт |
| 🟠 4 | T1.1 арифметика | H при MUL/UMUL/DIV, деление на ноль, ADC/SBC |
| 🟠 5 | T1.6 ветвления | 16 условий, обнуление двух младших бит адреса, PC+4 в R15 |
| 🟡 6 | T1.5 память | байт/слово, знак 20-битного смещения |
| 🟡 7 | T1.3 сдвиги | ASR со знаком, сдвиг на 0 и на 31 |
| 🟡 8 | T1.8 MOV-варианты | `MOV a,NZCV` возвращает `{N,Z,C,OV, 20'b0, 8'h53}` — константа **0x53** |
| 🟠 9 | **невыровненный доступ** | `SRadr = adr[19:2]` — младшие два бита молча отбрасываются, ошибки нет. Зафиксировать тестом |
| 🟠 10 | **байтовые лейны** | `inbus1`/`outbus` мультиплексирование + `SRbe` — классическое место ошибок |
| 🟠 11 | **IRQ во время многотактной операции** | `intAck & ~stall` → задержка до 34 тактов на DIV; там же проявляется незапоминаемый `H` |
| 🔴 12 | **эквивалентность декодера** | все 256 комбинаций {IR[31:28] × op} со случайными операндами: старое и новое ядро совпадают побитово, кроме новых кодировок. **Полчаса, ловит весь класс ошибок кодирования** |

## 5. Тесты новых инструкций

### T1.9 FMAC — ⏸ вынесено в выпуск №2

FMAC исключён из первого выпуска (ускорение опровергнуто: потолок Амдала 2.00×,
реализуемо 1.00–1.07×). Тест сохранён для будущего.

**Старый черновик:**
```
; FMAC a, b, c  ->  Ra = Ra + Rb * Rc
; Ключевой вопрос: совпадает ли результат с последовательностью FML+FAD?
        ; вариант 1: через существующие инструкции
        FML  R3, R1, R2
        FAD  R4, R0, R3
        ; вариант 2: новая инструкция
        MOV  R5, R0
        FMAC R5, R1, R2
; EXPECT R4 = R5          <- если НЕ равно, FMAC округляет иначе
```

⚠ Если слитная операция округляет один раз, а пара — дважды, результаты **законно**
разойдутся. Это надо решить до реализации: (а) делать FMAC с двойным округлением, чтобы
он был побитово эквивалентен паре (проще для эксперимента, честнее для сравнения);
(б) делать настоящую слитную операцию (точнее математически, но меняет вывод модели —
см. T5).
**Предварительно: вариант (а)** — цель эксперимента измерить скорость, а не точность.

### T1.10 CHK
```
; CHK a, b, c  ->  ловушка если Ra >= Rc (беззнаково)
        MOV  R1, 5
        MOV  R2, 10
        CHK  R1, R0, R2        ; 5 < 10, проходит
; EXPECT no_trap
        MOV  R1, 10
        CHK  R1, R0, R2        ; 10 >= 10, ловушка на границе
; EXPECT trap
        MOV  R1, -1            ; 0xFFFFFFFF
        CHK  R1, R0, R2        ; беззнаковое: огромное >= 10, ловушка
; EXPECT trap
```

✅ **Закрыто ревью, и ответ другой.** Ловушку через вектор `0x04` сделать **невозможно**:
маскируема (CLI), не принимается при `stall`, молча проглатывается внутри обработчика
(`~intMd`), а `SPC` **программно нечитаем** и хранит *следующий* PC.

**Правильная семантика уже есть в системе:** ловушки Oberon программные, через
`Put3(BLR, cond, ORS.Pos()*100H + num*10H + MT)`, вектор установлен по адресу `0x20`.
→ **CHK аппаратно делает `R15 := PC+4; PC := R12`**, номер ловушки в `IR[7:4]`.
`Kernel.Trap` уже умеет разбирать. Две строки в `pcmux0`, одна в `regwr`.

🔴 **CHK обязана иметь форму F1** с 16-битным непосредственным пределом — в форме F0
экономия нулевая (предел массива константа, сегодня идёт прямо в immediate у `Cmp`).
🔴 **CHK не должна писать регистр** — иначе затрёт N/Z.

## 7a. Тесты, которых не было в 0.1

- **«немодифицированный образ на новом RTL»** — новая ISA не должна ломать старые бинарники. Обязательно: **ловушки на неизвестную инструкцию в RISC5 нет**, неверная кодировка исполнится молча
- **«новый образ на старом CPU» должен ЯВНО ОТКАЗАТЬ** — использовать байт версии `.rsc` (`versionkey = 1X` → поставить **`2X`**), иначе старый загрузчик исполнит новую инструкцию как старую
- **детерминизм компилятора**: два прогона одного исходника → идентичные `.rsc`. Без этого T-BOOT-3 неинтерпретируем
- 🔴 **диффтест самого компилятора** между тремя реализациями: нативный Oberon / Norebo / `fzipp/oberon-compiler` (Go). Ловит ошибки правки кодогенератора **до** того, как они станут зависанием ОС
- переполнение `ORG.maxCode = 8000` слов и `maxStrx = 2400` после вставки CHK
- **покрытие** `verilator --coverage`
- **ассершены**: «intAck никогда при stall», «не более одного источника stall», «regwr не совпадает с wr», «ben только при F2»
- 🔴 `--x-assign unique --x-initial unique` со случайным seed — **Verilator двухзначный и принципиально не может проверить требование «все регистры сброшены»**

## 7b. Самораскрутка — уточнённая механика

Это **штатный режим** Project Oberon, не подвиг. Но:
```
gen0: ORP.Compile ORS.Mod/s ORB.Mod/s ORG.Mod/s ORP.Mod/s ~   (* /s обязателен *)
System.Free ORTool ORP ORG ORB ORS ~                          (* иначе res=3 *)
gen1 пересобирает себя → gen2; сравнить побайтово
```
🔴 `Files.Register` **перезаписывает `.rsc` на месте, старых версий нет** → сломанный новый
`ORP.rsc` = компилятора больше нет. Для конфигурации с CHK **кирпич реален** → вторая копия
образа и хост-маршрут обязательны.
🔴 Фикспойнт доказывает, что компилятор — **свой** фикспойнт, а не что он корректен.
Сравнивать только gen N и gen N+1 **одного исходника** (`.rsc` содержит `ORS.Pos()`).

## 8. Что оснастка НЕ проверяет (осознанно)

- Тайминги реального железа (для этого нужна ПЛИС)
- Поведение при метастабильности и на границах тактовых доменов
- Корректность синтеза (для этого — формальная проверка эквивалентности, отдельный этап)
- Энергопотребление
