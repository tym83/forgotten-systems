# Веха: настоящий Verilog Вирта загружает настоящую систему Оберон

Не эмулятор. Ядро `RISC5.v` от 31.8.2018, синтезируемое, прогоняемое Verilator'ом
такт за тактом, поднимает Project Oberon 2013 с образа диска и рисует свой интерфейс.

Запуск: `build/obj_soc/soc_tb --prom=rtl/prom_sd.mem`
Снимок экрана: `docs/oberon-boot-screen.png`

## Результат

| | |
|---|---|
| инструкций до загрузки | 12 000 000 |
| тактов | 18 654 115 |
| первая запись в кадровый буфер | около инструкции 7 077 888 |
| время на хосте | **4.27 с** |
| **скорость** | **4.37 МГц-эквивалент** (полное ядро с памятью) |
| чёрных пикселей на экране | 2.37% — характерно для оберонского белого фона с текстом |

Для сравнения: эталонный эмулятор `pdewacht/oberon-risc-emu` рисует первый кадр
после ~8 млн инструкций. Наше RTL — после ~7.1 млн. Порядок совпадает.

## Как устроен стенд

Проводные интерфейсы **не эмулируются**. По рекомендации ревью периферия подменена
заглушками с тем же регистровым интерфейсом к шине (адреса те же), а данные подаются
напрямую из C++:

| Устройство | Как в RTL | Как у нас |
|---|---|---|
| дисплей | пиксельный поток VGA из `VID.v` | чтение области кадрового буфера прямо из ОЗУ |
| клавиатура, мышь | битовый PS/2 | регистры 6 и 7 |
| диск | битовый SPI + автомат SD-карты | словная логика из эталонного эмулятора (`tb/disk/disk.c`) |
| RS-232 | битовый приём-передача | регистры 2 и 3 |

Ядро `RISC5.v` при этом **не тронуто** — а именно оно предмет исследования.
Заодно это вернуло скорость: без `VID.v`, честно тактующего пиксельный поток
1024×768@60, симуляция идёт заметно быстрее.

## Три ошибки по дороге

**1. Не тот загрузчик.** В комплекте Вирта `prom.mem` — загрузчик по последовательной
линии: он крутится в цикле опроса регистра состояния RS-232 и с диска не читает вовсе.
Нужен другой, из эталонного эмулятора (`risc-boot.inc`, 383 слова), — он грузится с SD.
Оба начинаются одинаково и различаются дальше, так что подмена не очевидна.

**2. Шина во время сброса.** Регистр команд защёлкивается **каждый такт**
(`RISC5.v:173`: `IR <= stall ? IR : codebus`). Если во время сброса подавать на шину
нули, первая же инструкция выполнится как `MOV R0, R0` вместо перехода из загрузчика,
и система тихо пойдёт исполнять нули. Проявляется как «загрузчик завис», хотя он
даже не начинался.

**3. Кадровый буфер снизу вверх.** `VID.v`: `vidadr = Org + {3'b0, ~vcnt, hword}` —
строка 0 лежит по максимальному адресу. Наивная выгрузка даёт перевёрнутый экран.
Ревью это предсказывало; предупреждение сэкономило день.

## Что это открывает

- **дифференциальный стенд**: теперь есть на чём гонять эталон против RTL на реальной системе, а не на синтетических тестах
- **браузер**: та же модель собирается Emscripten'ом, скорость 4.37 МГц на хосте оставляет запас
- **измерения на реальной нагрузке прямо на RTL**, а не через модель латентностей
