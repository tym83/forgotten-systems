# Находка 33. Подключаемый каталог для Cozystack

## Замысел

Отдельный каталог приложений, куда складываются вещи, которых нет и не будет в
основном: эмуляторы никогда не выпущенных архитектур, операционные системы,
оставшиеся на бумаге, и языки без реализации. Каждая — не архив, а
разворачиваемое окружение.

## Что выяснилось про механику Cozystack

Механизм для этого уже существует, и это важнее самого замысла.

Из дорожной карты платформы: **«Community application marketplace» намечен на
2027 Q1, дизайн-пропозалы лежат в `cozystack/community`, открыты и не
смёржены**. Консоль строится на **динамическом обнаружении через
`ApplicationDefinition`**. Есть прецедент отдельного каталога — `ccp`,
маркетплейс плагинов.

В дереве платформы лежит готовая механика:

* `PackageSource` (`cozystack.io/v1alpha1`) — объект, указывающий на
  OCI-репозиторий с пакетами и перечисляющий компоненты по вариантам;
* `ApplicationDefinition` — описание приложения для консоли: схема значений,
  ссылка на чарт, категория, иконка в base64, порядок полей формы;
* `cozypkg tap <oci-ref>` / `untap` — **подключение и отключение стороннего
  источника**. Официальные источники отключить нельзя: у них защитная метка;
* `cozypkg validate` — валидатор именно **внешнего** репозитория приложений;
* пакет `internal/marketplace` — механика не эскиз, а код.

Ссылка на чарт складывается по правилу
`<источник>-<вариант>-<компонент>` с заменой точек на дефисы
(`internal/marketplace/naming`). Расходится — валидатор помечает её висячей.

## Что сделано

Каталог `~/projects/forgotten-systems/marketplace`:

```
sources/forgotten-systems.yaml              PackageSource
packages/apps/oberon-lab/                   чарт приложения
packages/system/oberon-lab-rd/cozyrds/...   ApplicationDefinition
```

Первое приложение — `oberon-lab`. Две части, включаются отдельно:

* **веб** — девять браузерных лабораторных и методичка, статика в образе на
  непривилегированном nginx (93,6 МБ);
* **задание** — прогон лабораторной, которой нужен Verilator: правка приходит
  `ConfigMap`'ом, `initContainer` раскладывает её по путям, второй копирует
  дерево проекта в том, рабочий контейнер идёт с корнем только для чтения.

`cozypkg validate .` — ноль ошибок, ноль предупреждений.

## Проверено на промах

Ноль ошибок сам по себе ничего не значит: валидатор мог просто не найти наши
файлы. Подменил имя ссылки на чарт на несуществующее — валидатор поймал:

```
[WARNING] ... ApplicationDefinition oberon-lab chartRef "nonsense-does-not-exist"
does not match any <packagesource>-<variant>-<component> defined in this repository
```

Значит он действительно читает и связывает наши объекты.

Отдельно проверяется схема значений: `helm template` с неверным `task`
обязан упасть.

## Побочная находка: helm 4 ругается на все чарты Cozystack

`cozypkg validate --helm-lint` падает на нашем чарте с
`invalid icon URL '/logos/oberon-lab.svg'`. Проверил, наш ли это дефект:

| чарт | ошибок helm lint | из них про иконку |
|------|------------------|-------------------|
| `nats` | 3 | 1 |
| `redis` | 2 | 1 |
| `kafka` | 2 | 1 |
| `mongodb` | 3 | 1 |

**Все собственные чарты Cozystack падают с той же ошибкой.** Это расхождение
helm 4 с конвенцией платформы: Cozystack намеренно разрешает путь вида
`/logos/foo.svg` внутрь чарта (`hack/update-crd.sh`), а helm 4 требует
полноценный URL.

Практическое следствие для платформы: `--helm-lint` на helm 4 сейчас непригоден
для проверки каталога — ни своего, ни стороннего.

## Чего нет

Образы никуда не публиковались, каталог в OCI не выкладывался, в кластере
ничего не запускалось. В `images` и в `OCI` намеренно стоит `REPLACE-ME`,
чтобы это нельзя было применить не глядя.
